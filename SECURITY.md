# Security policy

> 中文版：[SECURITY.zh-CN.md](SECURITY.zh-CN.md)

## What this project is

A **render-only** DSH plugin: it turns Markdown reports and DSH session excerpts into images. It makes no network requests, calls no remote API, and sends no telemetry.

Zero npm dependencies — `dependencies` is empty. The direct purpose is **no supply chain**: no third-party package to poison, no lockfile to audit, and `npm i` cannot introduce code you have not read.

## What leaves your machine

**Nothing, by default.**

The only outbound behaviour is invoking the locally installed Chromium-family browser to render a local HTML file and screenshot it to a local path. The browser runs as a child process with a local `file://` URL and nothing else.

No requests, no callbacks, no usage statistics.

## What it reads

| Input | Note |
|---|---|
| The Markdown file you pass | Whatever path you give |
| `<DSH_HOME>/sessions/**/session.v4.jsonl.zstd` | Only when exporting a conversation, only the file you name |
| `<DSH_HOME>/attachments/v1/objects/**` | Only with `--with-images`, to inline attachments |
| `<DSH_HOME>/profiles/*/node_modules/dsh-fact-check` | First-run probe **checks existence only**, never reads content |

## What it writes

| Output | Note |
|---|---|
| The output directory you name | HTML + PNG (or PDF) |
| `%LOCALAPPDATA%\dsh-card-export\readiness.json` | First-run probe result, outside the package |
| `%LOCALAPPDATA%\dsh-card-export\config.json` | Only when you run `tools/config.mjs --init/--enable/--disable` |

It does not write the registry, change system settings, or touch the DSH profile tree (installation is `dsh plugin add`'s job, not this package's).

## Risks in rendered content

**1. HTML passthrough (important).** Raw HTML in a report document **takes effect by default when you say so** — that is a deliberate layout capability (coloured text, `<br>`, `<mark>`, MathML). The cost: that HTML runs inside the local headless browser that takes the screenshot.

The tool therefore does not decide for you. When it detects raw HTML it **exits with code 4, writes no files**, and returns a question with two options (`--html on` / `--html off`). Rules of thumb:

| Document source | Choose |
|---|---|
| Written by you, or just generated by the model | `--html on` |
| Fetched from the web, given by someone else, unknown | `--html off` |

Detection is reported by category, and `<script>` / `<iframe>` / `<img>` / `<link>` / `<form>` are classified as **active** with an extra "prefer literal" warning.

**2. Transcript cards always escape.** Text inside `dsh-ui` cards goes through `inline(..., { html: false })`; `<img src=x onerror=…>` stays literal text, guarded by `tools/smoke-dshui.mjs`. That content comes from the session, not from an author writing HTML.

**3. Embedded base64 and very long text.** A session may contain `data:` URIs or tens of thousands of characters of output. The default is to elide and label (`[内嵌图片/数据，已省略 N 字符]`, `默认 1200 字截断`) so the image does not become hundreds of MB. `--max-chars 0` disables truncation at the cost of file size.

Note also that the produced HTML is a **local file**: if you distribute the intermediate HTML, the recipient's browser decides what happens when they open it — outside this project's scope.

## Sandbox and privilege

- In containers, if the first render fails with sandbox symptoms the plugin appends `--no-sandbox --disable-dev-shm-usage` for **one retry**. Those flags **weaken browser isolation**, so they are used only after a failure and never by default. They are visible in `--dump` output and the result (`containerRetry: true`).
- The plugin requests no elevation and never changes DSH approval policy.

## Reporting a vulnerability

**Do not open a public issue.** Use either:

- GitHub private vulnerability reporting: <https://github.com/7starsseeker/dsh-card-export/security/advisories/new>
- Or email the owner's public address listed on their GitHub profile

Please include: affected version, reproduction steps, a minimal input (redacted as needed), and the impact you believe it has.

## Out of scope

- The **correctness of rendered content** (a wrong figure in the report) — that is a content problem, not a security one.
- Behaviour of the locally installed browser (font differences, browser vulnerabilities).
- What happens in a recipient's environment after you distribute an exported image or HTML.
