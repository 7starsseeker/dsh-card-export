# 报告图片化导出（RPC）

把 Markdown 报告变成图片。**只渲染，不改写**：不做摘要、不做推断、不改判定。

## 两套预设

`--preset auto`（默认 = `report`）。两套预设对应两类内容，不要混用：

| 预设 | 用于 | 产物 |
|---|---|---|
| `report` | **任意 Markdown 报告**（事实核查结论报告也走这套） | **两张图**：短图（结论）+ 长图（完整报告） |
| `generic` | **任意对话内容**：对话片段、随手一段回答、粘贴的核查报告原文、笔记……什么都能放 | 单张内容流图 |

`generic` 是「什么都行」的通道，因此对缺标题的内容要老实：

- 没有标题就**不硬编标题**（也不把首段当导语吃掉），原文第几段是第几段；
- 想要标题就显式 `--title`；
- 核查报告也能用 `generic` 输出——那时它不套结论卡，就是一篇内容。

### report 预设：为什么是两张

- **短图**——在尽量小的版面里给出足够信息：标题 + 结论段 + 章节目录 + 规模。结论段**只在报告确实有「结论 / 一句话总结」小节时**才标「结论」；没有就如实标「导语」。短图只做提取，不做改写。
- **长图**——**严格按原报告的排版、结构、内容与顺序**逐段还原：不重组、不删减、不改写、不替作者总结。报告里是什么样，长图就是什么样。

自动判定：命中「一句话结论 / 哪些是真的 / 来源」中**任意两段**，按事实核查报告处理（多出结论徽标、断言分档、甲乙双轨），仍是 `report` 预设，不是第三套皮；缺的段会在长图末尾列出（`为什么会这样` 在模板里写明可选，不算缺段）。fact-check 2.0.0 起一份报告可能是六种骨架之一：**只有裁决骨架有出图锚点**，其余五种走普通 `report` 预设，这是预期行为，不要给它们自创锚点。

英文报告等价锚点：`One-line verdict` / `What is true…` / `Sources`，同样**任意两段**即命中，走同一套皮肤、同一套判定语义，只是标签整套换成英文。判定档位（Confirmed / Likely true / Unconfirmed / False / Unverifiable）在内部映射回固定语义，颜色与图标不变。

### 语言：跟着报告走，不跟界面走

**默认由报告自己的二级标题判定**（`lib/modes/i18n.mjs`）：先数中英锚点各命中几个二级标题，多者胜；都没命中时退回字符占比（CJK ≥ 20% 判中文，否则英文）。所以**同一份报告，标题写什么语言，图上 chrome 就是什么语言**——不需要额外参数。

- 需要覆盖时：`--lang zh|en`（只影响标签与 chrome；档位解析两种词表都认，强制语言不会把对方写法的档位解析成「无法核实」）。
- 中文产物与改造前逐字节一致（`sample-report` 的 PNG 哈希不变）；英文产物不含任何中文标签，中文产物不含英文标签，两条都有 smoke 断言守着。
- 字数口径跟着语言：中文「约 N 字」数汉字，英文「About N words」数词。

## 短图：先写 brief，再渲染

**渲染器不会总结。** 想要一张真的「读完这份报告该知道什么」的短图，你必须自己读完再写一份 brief，渲染器只负责排版。

```bash
# 1) 读全文，写 brief.json（见下）
# 2) 渲染
node tools/render-report.mjs <report.md> --out <dir> --brief brief.json --png
```

```json
{
  "by": "读完 N 行全文后撰写",
  "conclusion": "一句话：这份报告到底在说什么（不是它有几节）",
  "points": ["该知道的第 1 件事", "第 2 件事", "第 3 件事"],
  "numbers": [{ "label": "指标名", "value": "61% → 84%" }],
  "caveat": "本次覆盖不到的边界"
}
```

写 brief 的纪律：

- **不准引入原文没有的结论**；每条要点都要能在原文找到依据；
- **数字照抄原文**，别顺手四舍五入或换单位；
- 写「读完该知道什么」，不要复述目录（目录渲染器自己会排）；
- 要点 3–5 条。超过 5 条说明你还没提炼完，不是报告太长。

没给 `--brief` 时，短图退化为**原文提取**（标题 + 首个结论/导语段 + 目录），kicker 会写「原文提取」、页脚写明"未做改写与推断"——它不会假装自己是摘要。

**事实核查报告**：它本身结论先行，短图默认直接用报告自带的档位 / 双轨 / 判断，**不需要额外写 brief**。若确实想让判断更聚焦，可以给 brief——它会覆盖 2–3 行判断与一句话总结，但**档位与甲乙双轨永远取自报告**，那是判定，不能被摘要改写。

## 超长报告：不切分，靠分隔线

长图**永远是一张**。超过 **12000px** 时工具只给一条提示，不改产物形态。需要分段由人手动裁——图上已经画好参照：

- 报告在**每个二级小节（`##`）之间**画一条通栏细线；
- 对话在**每轮之间**画同样的线。

它看起来就是普通的分节符，同时因为线到卡片左右边缘、完全水平，直接沿它裁不会切歪。

必须知道的四条：

- **线永远在内容单元边界**，不会落在半句话或半张表格中间。
- 短图不画线（一屏说完的东西不需要裁）。
- `--split` 已取消；传入只会收到一句说明，不会产出多张图。
- 事实核查报告的长图同样适用（按它自己的小节边界画线）。

要更短的图，只能缩小输入（`--preset generic`、拆报告、`--last/--turns` 缩对话范围），不要指望工具切。

## 太长怎么办：默认整张，先问再裁

**默认产物永远是整张长图**（`summary.png` + `full.png`，或事实核查的封面 + 详情）。渲染路径**不会**自己产出分段文件。

裁切是一个**需要用户点头**的动作，顺序不许颠倒：

### 第 1 步：出图，读 `tooLong`

只有内容确实过长（长图 > 12000px）时它才存在：

```json
"tooLong": {
  "heightPx": 13940,
  "cutLines": [{ "index": 1, "cssY": 937 }, { "index": 2, "cssY": 2120 }, …],
  "ask": "这张长图 13940px，是否太长？…",
  "how": "node tools/crop-image.mjs <图> --at <线序号> 或 --max <目标高度>"
}
```

### 第 2 步：在对话里问，等答复

把 `heightPx`、线数量、你建议的切法一起说清楚，例如：

> 这张长图 13940px（14 条分隔线）。要切成 3 段吗？按小节分：1–6 节 / 7–11 节 / 12 节起，每段约 4000–6000px。

**不许不问就切，也不许切完再汇报。** 用户没回复就保持整张。

### 第 3 步：得到明确答复后才执行

`crop-image.mjs` 有硬闸门：**不带 `--confirmed` 一律拒绝执行**（退出码 3，一个文件都不产出），并在报错里把「高度 / 线数 / 计划几刀」返回给你——那正是你第 2 步要问用户的内容。

```bash
node tools/crop-image.mjs <长图.png> --lines                       # 只看线，永远可跑
node tools/crop-image.mjs <长图.png> --at 5,10 --confirmed         # 用户同意后
node tools/crop-image.mjs <长图.png> --max 5000 --confirmed
```

裁切沿线上切、**线本身整行丢弃**，接缝不留灰边、不出现半句话。

### 怎么选切点

- **优先按结构**：`cutLines` 序号就是小节顺序（第 1 条线 = 第 1 节末尾），照报告目录把同类小节归一段；
- **再按高度**：太短就并到相邻段，太长就往前找一条线；
- **`--max` 会如实报 oversized**：某节本身比目标高时无法再分（节内没有线），工具会说明哪段、多高，不硬切内容。

需要目视确认可用 `read_image`，但**位置以 `cutLines` 为准**——预览会缩放，像素坐标不可靠。

## 出图

```bash
node tools/render-report.mjs <report.md> --out <dir> --png --width 960

# 强制预设 / 指定标题
node tools/render-report.mjs <report.md> --out <dir> --preset generic --title "标题" --png

# 强制标签语言（默认按报告标题自动判定，一般不用给）
node tools/render-report.mjs <report.md> --out <dir> --lang en --png
node tools/render-report.mjs <report.md> --out <dir> --lang zh --png

# 只要 HTML（无浏览器环境也成立）
node tools/render-report.mjs <report.md> --out <dir>
```

产物命名：`<stem>.summary.png` + `<stem>.full.png`（report）；`<stem>.report.png`（generic）。同目录保留同名 `.html`。

## 支持的 Markdown

标题（`#`–`#####`、Setext `===`）、段落、无序/有序列表（含续行、嵌套、项内空行+缩进的表格）、表格（含 `\|` 转义、无首尾竖线、对齐标记）、引用、围栏代码块、分隔线、脚注（`[^1]` + 文末注释区）；行内 `**粗体**`、`*斜体*`、`~~删除线~~`、`` `代码` ``、`[文本](链接)`、`<https://…>` 自动链接、`![图](…)`（渲染成引用标记）、`[n]` 角标（上标）。

**代码块里的内容永远字面输出**，不做任何渲染——公式、HTML、Markdown 都原样显示。

## HTML：出图前先问，不擅自决定

文档里的原始 HTML（`<span style>`、`<br>`、`<mark>`、MathML 公式）**默认不会生效**——工具会在出图前拦一下。

### 流程（三步）

**1. 直接跑导出。** 如果文档里有 HTML，命令会**退出码 4 且不产出任何文件**，返回一个 `htmlAsk`：

```json
"htmlAsk": {
  "detected": 304,
  "breakdown": ["MathML 公式 304 个标签", "排版标签 3 个（<br> <mark> <span>）"],
  "hasActive": false,
  "question": "这份文档里有原始 HTML（…）。要让它们真的生效吗？…",
  "options": [
    { "flag": "--html on",  "meaning": "生效（彩色文字、<br>、<mark>、MathML 公式会渲染）" },
    { "flag": "--html off", "meaning": "全部按字面显示（来源不明的文档选这个）" }
  ]
}
```

**2. 把 `question` 转述给用户**，等他选。`hasActive: true`（出现 `<script>` / `<img>` 等）时，`question` 里已经带了「建议选字面」的判断——照实转述，不要淡化。

**3. 按答复重跑：**

```bash
node tools/render-report.mjs 报告.md --out ./out --png --html on     # 用户同意生效
node tools/render-report.mjs 报告.md --out ./out --png --html off    # 全字面
```

只想看有没有 HTML、不出图：`--preflight`（返回 `html` 统计，退出码 0）。

### 规则

| 文档来源 | 建议 |
|---|---|
| 你自己写的 / 模型刚生成的 | `--html on` |
| 网页抓取、他人提供、来源不明 | `--html off`（等价旧 `--no-html`） |

`--html off` 之后，行内 HTML、块级 HTML、MathML 全部退化为字面文本。
对话导出的 `dsh-ui` 卡片**永远转义**，不受此开关影响。

**代码块里的内容始终字面输出**，与开关无关。

## 数学公式：转成 MathML，零依赖可排版

Chromium 内置 MathML 排版引擎，所以只要把公式写成 MathML，**不需要 KaTeX / 联网 / 额外依赖**。

LaTeX → MathML 的最小映射（转写后必须回读核对符号是否一致）：

| LaTeX | MathML |
|---|---|
| `\frac{a}{b}` | `<mfrac><mi>a</mi><mi>b</mi></mfrac>` |
| `x^{2}` / `x_i` | `<msup>…</msup>` / `<msub>…</msub>` |
| `\sqrt{x}` | `<msqrt><mi>x</mi></msqrt>` |
| `\sum_{i=1}^{n}` | `<munderover><mo>∑</mo>…</munderover>` |
| `\int_0^1` | `<msubsup><mo>∫</mo>…</msubsup>` |
| `\le \ge \times \pm` | `≤ ≥ × ±`（直接写字符） |
| `\text{中文}` | `<mtext>中文</mtext>` |
| 字母 | `<mi>x</mi>`；数字 `<mn>2</mn>`；运算符 `<mo>+</mo>` |

独立公式用 `<math display="block">`，行内用 `display="inline"`。

**已知版式差异**（实测 8 条常见公式语义全部正确）。两处版式问题可以用属性修正：

| 想要 | 写法 |
|---|---|
| 求和/连乘的上下限堆叠到符号上下 | 给 `<math>` 加 `displaystyle="true"`（不加就排在符号右侧） |
| 括号随内容伸缩 | `<mo stretchy="true">(</mo> … <mo stretchy="true">)</mo>` |

`--html off` 时公式会按字面显示——这是预期行为，不是 bug。

## 出图前先读环境结论

首装时插件已探过一次，结论在 `<配置目录>/readiness.json`（含 `renderLevel` 与 `factCheck` 两项）：

| renderLevel | 实际能拿到什么 |
|---|---|
| `png` | 正常出 PNG |
| `pdf` | 只能出 PDF（无高度上限，但按 A4 排版，不是长图） |
| `html` | 只能交付 HTML，需自行截图或打印 |

`factCheck` 记录本机是否装了 dsh-fact-check（`true` / `false` / `unknown`）：

- `true` → 核查报告会走结论卡短图（档位 + 双轨 + 分档）；普通报告不受影响。
- `false` → 一切照旧，任意 Markdown 报告都能出短图 + 长图，**功能不缺**。
- `unknown` → 定位不到技能目录（如未设置 `DSH_HOME`），按普通报告处理。

想重测：`node tools/doctor.mjs`。容器里没装 Chromium 时它会给出对应发行版的安装命令。

## 交付前回检（不看就交 = 没验证）

1. **读图**：打开看一眼。factcheck 版看**两张图顶部的档位是否一致**（报告给了多档时，长图顶部要挂出全部档位，不能只剩第一档）、首图档位徽标与双轨有没有挤成两行；**英文版再扫一遍有没有中文标签残留**（徽标、小节标题、页脚三处最容易漏）；generic 版看表格有没有溢出。
2. **逐字抠措辞**（数字与量词）：
   - 量词配对象：人用「位 / 个 / 名」，不用「条 / 只」；
   - 单位不许偷换：条数 ≠ 人数、账号 ≠ 人，写「N 个人」前先数去重后的主体；
   - 覆盖面写清分母与口径（「没有带薪年假」≠「一天带薪假都没有」）；
   - 百分比写清基准；
   - 比较类数字标混杂因素，否则加「约」；
   - 未核实的显式标注，不用「据说 / 普遍认为」；
   - **标题与导语单独再查一遍**。
3. **修辞不得改变事实**：为让标题响亮而改动词汇，即使逐字可查证，也已经错了。

## 已知边界

- **不发散**：报告没写的，图上不会有。
- **factcheck 预设的语义色固定**：五档判定色不随主题变化；且五色亮度彼此接近（1.02–1.29），所以每档都同时带图标、文字与底纹，**颜色永远不是唯一区分手段**。
- **`⚠️未证实` / `❓无法裁定`** 带底纹与「不得在任何转述中被当作事实引用」，防断章引用，不是装饰。英文版是 `Unconfirmed` / `Unresolved` + `Must not be cited as fact in any retelling`。
- 报告缺段不补：三段特征标题（`一句话结论` / `哪些是真的` / `来源`，英文对应 `One-line verdict` / `What is true…` / `Sources`）**命中少于两段**时按普通 `report` 预设处理（两张图，但没有结论卡）；命中两段或以上就走结论卡，缺的段在长图末尾列出，不会整份降级。没有「强制 factcheck 预设」这种开关——要逼出结论卡，就把报告写成模板结构。
- **不是所有段落都进固定槽位**（fact-check 2.0.0 起）：裁决之外的骨架段（`## 总览`、`## 核心发现` 等，Step 4c 多产物编排会产生）**按原文顺序附在长图末尾**，编号 `附 1`、`附 2`，短图会写明有几段附录；报告开头的前置块（`【定型】` 定型卡、`定型：A → B` 改型声明、`核查口径` 声明）按原文画在长图顶部，加「定型与前置声明」标签；没有这些标记的随意前言不画。
- **其余五个骨架的短图靠「导语卡」而不是新皮肤**：认出骨架后，把该骨架自己声明的结论段抬到短图（释义 `## 一句话定义`／地图 `## 核心发现`／指标卡 `## 数值`／因果 `## 主因`→`## 落地概率`→`## 因果链`／对照 `## 分场景结论`），标签写「骨架名 · 段名」。**只抬原文，不造档位、不做双轨**——那是裁决骨架专属，`SKILL.md` §4b 明令不许给其它骨架自创锚点。识别门槛是「该骨架独有标题命中 ≥2 段」，共享标题（`## 定界`、`## 来源`、`## 缺口`、`## 可比性检验`）不参与；认不出就逐字退回普通文档，没有「强制某种骨架」的开关。
- **详图的强化要素按骨架对应**，换的只是摆放方式：指标卡 `## 数值` → 数字卡、地图 `## 确定性分层` → 分层条、因果的被排除成因／对照的 `## 不可比`／释义的 `## 常见误解` → 灰底块。文字仍逐字来自原文、不合并不重排；识别表与强化表都在 `lib/modes/skeletons.mjs`，没有为哪个骨架单独写解析器。
- **识别表优先读上游声明的**：fact-check 的 `reference/skeleton-anchors.json`（与它 `SKILL.md` 由 `lint-skill` 断言同步）→ 读不到用内置同内容副本 → 内置表也认不出就逐字退回普通文档。匹配规则是 `stripTrailingParenThenExact`：剥末尾括号说明后**全等**，不做前缀/子串；`来源` 只留给裁决，`定界` / `缺口` / `可比性检验` 任何骨架都不许用来识别（`## 来源` 在 4-E / 4-M / 4-S 正文里确实存在，误用会把释义报告渲染成判决书）。
- **英文档位词比汉字长**：徽标块在 `html:lang(en)` 下放开宽度、收掉字距；这是唯一的语言相关样式差异，判定色与图标不变。
